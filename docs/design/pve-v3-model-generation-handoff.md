# PVE V3 模型生成交接

## 边界

本文件只交接模型资产生成与人工视觉验收。战斗逻辑、四类确定性场地、敌人跳台导航、弹道掩体、六动作槽位、程序化回退和自动测试已经在代码中完成。接手人不得把模型调用成功等同于动作可用，必须按本文逐项验收。

本轮没有继续调用模型。此前已有一次真实生成记录：敌人档案 `pve_07f3ffc153`，资产 `ast26366`，名称“机械守卫”。该记录可能停留在 `generating_actions`，接手人应先检查状态，不要直接重复提交整只敌人。

## 动作契约

| 运行时槽位 | 生成身份 | 视角 | 循环 | 验收重点 |
|---|---|---|---|---|
| `idle` | 基础动作 `idle` | side | 是 | 脚底稳定、轮廓不漂移 |
| `walk` | 基础动作 `walk` | side | 是 | 朝向一致、步频连续 |
| `windup` | 自定义动作 `custom:windup` | side | 否 | 至少 350ms 的明确蓄力姿态 |
| `attack` | 基础动作 `attack` | side | 否 | 有效动作与运行时 active 窗口对齐 |
| `hurt` | 自定义动作 `custom:hurt` | side | 否 | 受力方向清晰，不改变角色身份 |
| `death` | 自定义动作 `custom:death` | side | 否 | 非循环，最终姿态可保持 |

前端会把三个 `custom:*` 身份自动映射到对应槽位；缺失时分别使用压缩蓄力、受击倾斜和倒地淡出回退。基础动作可在 PVE 敌人工坊中单独重建，不需要重建模型或其他动作。

## 执行顺序

1. 打开资产 `ast26366`，确认 `design_views.side` 是真实侧视图。若缺失，先补侧视图；不要用正面图冒充侧视图，后端已禁止这种回退。
2. 查询敌人档案 `pve_07f3ffc153`。若已有动作批次仍在运行，先等待其终态并检查失败原因；只有终态后才能重建。
3. 在敌人工坊分别重建 `idle`、`walk`、`attack`。每次只提交一个动作，并确认完成后再提交下一个。
4. 在动作工作台创建名称严格为 `windup`、`hurt`、`death` 的三个自定义动作，绑定资产 `ast26366`，使用 side 视角生成。名称不可翻译或加后缀，否则运行时不会自动映射。
5. 进入任意 PVE 场景，确认浏览器请求返回的条带键包含 `idle`、`walk`、`attack`、`custom:windup`、`custom:hurt`、`custom:death`。
6. 实战检查蓄力、命中、死亡。每个动作至少观察三次；Boss 和普通敌人都要检查，不得只看动作预览页。

## 人工验收记录

完成后在本节追加日期、执行人、模型名称、六个动作的动画 ID、失败重试次数，并保存以下证据：

- 侧视源图截图。
- 六动作条带预览截图。
- 普通敌人前摇、受击、死亡各一张实战截图。
- Boss 第二阶段及掩体拦截弹道截图。
- 桌面端完整通关结果。
- 390px 宽移动端完整通关结果，包含触控移动、跳跃、射击、防御、闪避和上下瞄准。

## 不得回退的规则

- 不得把正面源图记录为 side。
- 不得用同一条攻击动画复制成 `windup / hurt / death`。
- 不得删除程序化回退；它用于旧资产兼容和模型失败降级。
- 不得绕过动作终态检查并重复计费提交。
- 不得用接口 200、批次 done 或截图展示代替完整通关。
