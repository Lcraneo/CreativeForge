# 生成模块提示词注意事项：角色 / 跑酷场景 / PVE 场景 / PVE 敌人

> 适用范围：CreativeForge 的「生成角色」「场景工坊（跑酷）」「场景工坊（PVE 2.5D 三关）」「PVE 敌人工坊」四个生成入口。
>
> 说明：本文只讲**用户输入提示词的写法与边界**，以及各模块**代码内置固定提示词**对输入的影响。内置提示词不要随意改写；它们与三视图、背景一致性、敌人轮廓识别、缓存与额度直接相关。

---

## 0. 先分清两类提示词

| 类型 | 谁来写 | 例子 | 注意 |
| --- | --- | --- | --- |
| 用户输入 | 用户 | 角色描述、场景主题、敌人描述 | 只描述画面与设定，不写工程指令和数值 |
| 代码内置 | 代码 | 三视图指令、场景背景拼装、敌人风格尾缀、动作词表 | 由代码统一追加，用户无法覆盖，不要试图在输入里"抢写" |

四个模块的关系：

1. **角色生成** = 用户一句话（+ 可选正面参考图）→ 角色原画 → 自动生成侧/背三视图 → 下游动画与引擎导出。
2. **跑酷场景** = 用户一句话 → 对话模型解析关卡语义 → 代码编译路线 → 按语义生成 3/5/7 张连续背景。
3. **PVE 场景** = 用户一句话 → 同样的语义解析 → 固定三关战役 → 每关一张 2.5D 战场背景 → 从敌人工坊匹配阵容。
4. **PVE 敌人** = 用户描述 + 角色类型 + 难度 → 对话模型提取标签/行为/元素 → 生成原画 → 生成怪物三视图 → 生成动作。

## 1. 角色生成（一句话 + 可选正面图）

### 1.1 写什么

一句话里尽量包含这些**画面属性**：

- 身份与气质：种族 / 性别 / 年龄感 / 职业气质
- 外观：发型、发色、瞳色、肤色
- 服装：款式、材质、主配色、纹样
- 配饰与武器：披风、护甲、法杖、弓、剑等
- 体型与构图：全身、站姿、居中
- 风格（需要时）：2D 动漫 / 像素

推荐结构：

```text
[身份/气质] + [发型发色] + [服装配色] + [武器配饰] + [风格]
```

示例：

```text
银白长发的精灵女法师，深蓝色星纹长袍，手持水晶法杖，清冷气质，2D 动漫风，全身立绘
```

```text
披重甲的人类骑士，黑色短发，暗金与铁灰配色，双手长剑与鸢盾，厚重威严，像素风
```

### 1.2 不要写什么

| 禁写内容 | 原因 |
| --- | --- |
| 侧视、侧面站立、背影、背面、回头、回头看 | 代码会把这类构图词删掉，因为角色原画必须是正面基准，供三视图使用 |
| 透明背景 / 透明 PNG | 文生图模型没有真 alpha，会忽略或生成怪背景；统一使用纯白/纯色背景 |
| 导入 Unity / Cocos / Godot / 游戏引擎 | 属于结构化字段，代码会从提示词中剥离，写进画面只会污染语义 |
| 画师名、工作室名、对标某款游戏 | 容易触发版权与风格模仿，且平台审核会拦截 |
| 具体 IP 角色名（皮卡丘、哆啦A梦等） | 现代版权角色名会被自动替换成视觉特征，写了也不生效 |
| 血腥、暴力、写实伤害描述 | 可能触发内容审核；审核失败会走安全改写重试，结果不可控 |

### 1.3 风格规则

- **未显式指定风格时，默认走像素风**：自由文本没提风格、风格选项也没选"自动"时，代码会追加像素风尾缀。
- 要 2D 动漫：提示词里明确写"2D / 动漫 / 插画 / 赛璐璐"，或在界面选择"2D 动漫"。
- 选择"风格：自动"时不会强制像素风，由模型自然发挥。
- 风格尾缀由代码按语言自动匹配（中文输入配中文尾缀），不需要自己再写一遍"像素风游戏素材、干净描边、有限调色板"。

### 1.4 超短输入

少于约 8 个字的输入会自动扩写为"全身立绘、居中构图、造型鲜明、服装配饰细节丰富"。因此：

- 「法师」「骑士」也能出图，但构图与细节由代码兜底；
- 想要可控结果，还是写完整的一句话。

### 1.5 上传正面参考图

- **参考图是唯一身份来源**：脸型、五官、发型发色、肤色、体型比例、服装款式与配色、配饰都会被锁定。
- 此时提示词**只描述姿势、动作与画面呈现**；不要用文字要求换脸、换发型、换服装、重新设计角色。
- 参考图质量要求：光线均匀、人物正面站立、面部和服装无遮挡的**全身图**。
- 参考图链路依赖可用的图片编辑模型；未配置时会直接失败并给出配置指引，不会静默退回纯文生图。
- 参考图模式同样要求角色从头到脚完整入画、纯白背景、无文字无边框无其他人物。

### 1.6 三视图（代码自动生成，用户无需写）

原画生成后，代码固定执行：

- 左栏：正右侧 90° 全身侧面像，角色**面朝画面右侧**；
- 右栏：正后方 180° 全身背面像，只可见后脑勺、发型背面与背部结构；
- 两栏必须是同一角色，发型、发色、服装、配色、武器、配饰、体型与身高比例完全一致；
- 全身入画、同比例同脚底线、白色间隔、纯白背景、无文字无边框无场景。

**注意**：

- 不要试图让用户提示词产出侧面或背面，原画必须是正面。
- 三视图固定使用专用编辑模型，失败会保留原画并直接报真实原因，可直接重试。

## 2. 场景工坊 · 跑酷

### 2.1 输入的用途

用户提示词不会直接变成图片提示词，而是先被对话模型解析成**关卡语义 JSON**：

- `title`：中文短标题
- `environment`：城堡 / 雪原 / 森林 / 熔岩 / 沙漠 / 城市
- `mood`：中文氛围
- `difficulty`：简单 / 普通 / 困难（**界面选择优先**）
- `length`：短 / 中 / 长（决定背景数量 3/5/7）
- `features`：缝隙、上升平台、浮空平台、长跳、冰面主题
- `palette`：天空上/下、地面、浮空、强调色，均为 `#RRGGBB`

代码再据此编译路线、校验可达性，并按镜头推进生成背景图。

### 2.2 写什么

- 世界主题与地貌：雪原、火山、森林、废墟城市、古堡
- 氛围与光线：黄昏、永夜、雾霭、冷蓝月光、熔岩红光
- 地标演进：从林间小径 → 冰封溪谷 → 古堡大门
- 色板倾向：冷蓝、暖橙、灰绿等
- 想要的节奏：短程紧张 / 中程探索 / 长程远征

示例：

```text
被永夜笼罩的雪原森林，冰封古堡废墟作为远处地标，冷蓝到深靛的夜空，
沿途从林间小径逐步推进到城堡大门
```

### 2.3 不要写什么

| 禁写内容 | 原因 |
| --- | --- |
| 平台数量、坐标、间距、跳法、碰撞 | 这些由编译器生成并校验，提示词不会进入路线 |
| 障碍物、怪物、金币、道具的具体摆放 | 背景图固定要求"无角色、无怪物、无文字、无 UI、无游戏障碍、前景通道清晰" |
| 每段换一个完全不同的世界 | 多张背景必须属于同一连续世界与同一美术方向 |
| 具体数值（速度、重力、跳跃高度） | 属于玩法参数，不在提示词解析范围内 |

### 2.4 环境与参数边界

- 环境词不在枚举内时会回退到"城堡"：写"太空""赛博"不一定被识别成想要的环境，最好用枚举内的词或明确地貌。
- 难度以界面选择为准；提示词里写"困难"不会覆盖界面参数。
- 冰原主题会自动补 `ice_theme`，不需要自己重复写特性列表。
- 提示词上限 2000 字。

### 2.5 背景图是代码拼装的

每张背景都会自动带上：

- 2D 横版平台游戏背景、16:9 宽幅；
- 无角色、无生物、无怪物、无文字、无 UI、无游戏障碍；
- 前景通道清晰；
- 同一连续世界与同一美术方向；
- 指定镜头：入口全景、早期地标、中段不同地标、纵深过渡、终点远景等；
- 主题、环境描述、色板、原始请求。

**用户只需要写"世界是什么样"，不需要写"画面里不要有什么"**——否定项已由代码统一处理。

## 3. 场景工坊 · PVE 2.5D 三关

### 3.1 固定玩法结构

- 固定三关：两关小怪 + 一关守关 Boss，不包含金币。
- 每关一张独立背景，三张背景不拼接、不混用。
- 敌人阵容从「PVE 敌人工坊」中状态为"完成"的资产里，按提示词语义匹配。
- 可手动替换敌人序列；旧版 PVE 场景需要重新生成后才能替换敌人。

### 3.2 写什么

- 三阶段的环境推进：林缘 → 深处 → 巢穴 / 要塞 / 王座
- 地表材质与地貌：腐殖土、菌毯、焦土、石板、雪地
- 光源与氛围：冷绿侧光、 ominous rim light、低雾、暗红天光
- 地标：巨型菌盖、残破拱门、远处要塞、Boss 巢穴焦点
- 配色倾向：暗绿、铁灰、暗红、冷紫

示例：

```text
腐化蘑菇森林深处，潮湿的暗绿色地表，巨大菌盖与盘根错节的根系，
三关从林缘逐步推进到菌母巢穴，冷绿色侧光，强烈纵深
```

### 3.3 必须遵守的画面约束（代码固定追加）

- 2.5D 固定斜俯视竞技场游戏背景；
- 16:9 宽幅；
- **一整块连续无缝的可行走地面**，从最近前景一直延伸到远处地平线；
- 低地平线 + 强透视纵深 + 高三分之四俯视角度；
- 无浮空岛、无分裂平台、无分层结构、无擂台环/边界、无角色、无怪物、无文字、无 UI、无游戏障碍、无台阶、无陷阱、无掩体道具。

### 3.4 绝对不要写 / 不要诱导

| 禁写内容 | 后果 |
| --- | --- |
| 浮空岛、漂浮平台、多层平台 | 会生成不可达区域，破坏 2.5D 走位 |
| 擂台、竞技场围栏、封闭坑、边界圈 | 会把全图切割成限制区域，角色无法全图移动 |
| 分裂平面、断崖、上下分层 | 背景会出现"分裂平面"，纵深失效 |
| 刷怪点、敌人数量、血量、掉落 | 不属于场景生成，由战役结构与敌人资产决定 |
| Boss 本体出现在背景里 | Boss 由敌人资产在运行时放置，背景只画场景 |
| 每关完全不同的世界 | 三关必须是同一世界的连续推进 |

### 3.5 镜头与关卡

三张背景固定对应：

1. 第一关：战场全景，连续地面从前景延伸到远方地平线；
2. 第二关：同一地面向敌境深处推进，地标与第一关不同，地面仍完整可行走；
3. 第三关：Boss 巢穴，连续地面通向远处焦点地标，带压迫感轮廓光与强纵深。

用户提示词负责"这个世界长什么样、三关如何推进"，不需要也不应该描述镜头角度和地面结构。

### 3.6 其他限制

- 提示词上限 2000 字。
- 背景生成失败会跳过该张并给出警告；全部失败时用主题色降级，可单独"带回提示词重试"。
- 旧版 PVE 场景不会被静默当作新版播放，避免页面崩溃。

## 4. PVE 敌人工坊

### 4.1 输入的作用

用户描述会先被对话模型提取成结构化属性：

- `name`：中文短名
- `summary`：中文一句话
- `tags`：仅限 `fast, ranged, flying, armored, ice, fire, toxic, beast, undead, construct`
- `behavior`：仅限 `chaser / shooter / charger / guardian`
- `element`：仅限 `physical / ice / fire / toxic / arcane / earth`

角色类型（小怪 / Boss）与难度由界面参数决定，代码据此计算血量、速度、伤害、攻击间隔、显示高度。

### 4.2 写什么

建议按"生物设定"来写：

```text
[生物类别] + [体型] + [标志性结构] + [肢体/器官数量] + [材质与配色] + [攻击方式] + [移动特征]
```

示例：

```text
菌类怪物，巨大红色菌盖，两条菌柄状下肢，四条藤蔓触须，喷射绿色孢子，
体型矮壮，腐烂质感，移动缓慢
```

```text
甲壳类冲锋兽，铁灰色厚重甲壳，六条节肢，头部一对巨钳，短距离高速冲撞，
背部有发光裂纹
```

### 4.3 不要写什么

| 禁写内容 | 原因 |
| --- | --- |
| 血量、伤害、速度、攻击间隔、掉落 | 由 `role + difficulty + behavior + tags` 计算，提示词不生效 |
| 坐标、出生点、关卡位置、波次 | 由战役结构决定 |
| "Boss / 小怪 / 精英" | 角色类型用界面选择，代码会追加角色说明；写在描述里容易冲突 |
| UI、血条、特效文字 | 背景固定要求无文字无 UI |
| 3D、写实、厚涂等非像素风格 | 敌人生成链路**强制像素风**，写其他风格会与固定尾缀冲突 |
| 人类肢体词描述非人形生物 | "单眼 / 双臂 / 双腿"会诱导模型补出原本不存在的肢体 |

### 4.4 封闭词表与回退

- 标签超出词表的会被丢弃；全部无效时使用回退标签。
- 行为、元素不在枚举内时使用回退值；描述里可以暗示，但不要指望模型一定给出某个枚举值。
- 语义分析失败时不会中断生成，会使用基于关键词的兜底分析。

### 4.5 风格与构图固定项

敌人生成时由代码统一追加：

- 角色说明（守关 Boss：压迫感体型；小怪：普通体型）
- 已提取的标签
- "2D 横版游戏敌人，单人全身，轮廓清晰，适合游戏剪影识别"
- "像素风与动漫平涂均可，纯白背景，无地面、无文字、无边框、无其他人物"

因此用户**不需要**再写"像素风、单人、全身、纯白背景、无文字"。

### 4.6 怪物三视图

敌人原画生成后走**怪物专用**三视图提示词：

- 以参考图中的怪物为唯一身份依据；
- 严格保留原有身体结构、肢体数量、器官、菌盖、甲壳、翅膀、尾巴、根系、配色与体型比例；
- **原本没有的肢体不得凭空增加**；
- 左栏正右侧 90°、右栏正后方 180°，全身（或到最低肢体/根系）完整入画；
- 纯白背景、无文字、无边框、无场景、无其他怪物。

**注意**：

- 不要让用户描述里出现与设定矛盾的肢体数量，例如"无腿"却写了"双腿"。
- 三视图失败会保留原画并暴露真实原因，可直接重试。

## 5. 四个模块的快速对照

| 模块 | 必须写 | 绝对不要写 | 代码自动处理 |
| --- | --- | --- | --- |
| 角色生成 | 身份、外观、服装、配饰、武器、风格 | 侧/背视角、透明背景、IP 名、引擎指令 | 正面构图、纯白背景、风格尾缀、超短扩写、IP 替换 |
| 跑酷场景 | 世界、地貌、氛围、地标演进、色板 | 平台数量、坐标、碰撞、障碍摆放 | 语义 JSON、路线编译、连续背景、否定项 |
| PVE 场景 | 三阶段环境推进、地表、光源、地标 | 浮空岛、擂台边界、刷怪点、Boss 本体 | 2.5D 斜俯视、连续地面、强纵深、三关结构 |
| PVE 敌人 | 生物形态、肢体数量、材质、配色、攻击方式 | 数值、坐标、Boss/小怪标签、非像素风格 | 标签/行为/元素提取、属性计算、像素风尾缀、怪物三视图 |

## 6. 常见错误示例

| 输入 | 问题 | 结果 |
| --- | --- | --- |
| 「生成一个像皮卡丘的角色，侧身站立，透明背景，导入 Unity」 | IP 名 + 侧视 + 透明 + 引擎指令 | 角色名被替换、侧视词被删、透明背景被忽略、引擎子句被剥离 |
| 「银发女法师，正面和侧面各来一张」 | 一句里要求两个视角 | 只保留正面基准，侧/背由三视图链路单独生成 |
| 「做一个三块浮空平台的擂台，周围一圈栅栏」 | 与 2.5D 连续地面约束冲突 | 背景出现浮空/分裂/限制区域，角色无法全图移动 |
| 「BOSS 血量 500，攻击力 30，放在第三关入口」 | 数值与位置不参与生成 | 数值被忽略，位置由战役结构决定 |
| 「写实 3D 风格的四足甲壳怪」 | 敌人链路强制像素风 | 风格尾缀冲突，出图仍偏像素风 |
| 「四条腿的菌类怪，没有手」 | 肢体数量明确 | 正确；三视图不会补手 |
| 「单眼双臂双腿的蘑菇怪」 | 用人类肢体词描述非人形生物 | 模型可能补出不存在的手脚 |
