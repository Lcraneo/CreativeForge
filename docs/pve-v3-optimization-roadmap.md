# CreativeForge PVE 第三版优化路线图

> 状态：方案  
> 日期：2026-10-31  
> 范围：2D 横版 PVE  
> 目标：把当前“可生成、可通关”的 PVE 升级为“每类敌人都有明确战斗语法”的可重玩模式

## 1. 当前基线

第二版已经具备：

- 独立 PVE 场景与试玩入口，不修改原有跑酷流程。
- 2 个普通遭遇战区与 1 个 Boss 区，支持区域封锁和清场推进。
- 自定义小怪、Boss 独立生成，拥有语义标签、数值和 `idle / walk / attack` 动作。
- 敌人序列自动语义匹配，并支持手动调整阵容。
- 单发远程攻击、单格防御、生命值、暂停、重试和胜负结算。
- 弹道拖尾、命中火花、受击闪白、击退、顿帧和合成音效。
- 背景平滑过渡、减少动态效果适配和敌人动作条带预打包。
- 当前回归状态：前端 139 项测试、后端相关 12 项测试通过。

## 2. 当前核心瓶颈

1. **敌人行为差异偏浅。**  
   当前行为主要改变移速、距离和射击参数，所有敌人仍共享近似的投射物攻击。

2. **Boss 缺少真正的守关机制。**  
   Boss 主要依靠更高生命值和体型形成压力，没有阶段变化、专属技能或独立战场规则。

3. **场地结构没有充分进入战斗。**  
   PVE 物理层目前只使用地面平台，浮台和高低差更多是视觉元素。

4. **玩家操作上限有限。**  
   当前只有单发能量弹和单格防御，熟练玩家会较快触达操作上限。

5. **敌人动作契约不足。**  
   自定义敌人主要生成正面 `idle / walk / attack`，缺少侧视、前摇、受击和死亡动作。

6. **生成后缺少战斗质量验证。**  
   当前校验能确认敌人有落点、遭遇战结构完整，但无法判断攻击是否可躲、战斗是否过长或是否存在无法处理的弹幕。

## P0：第三版必须完成

### P0-1 敌人技能与攻击前摇

#### 目标

让 `chaser / shooter / charger / guardian` 不只是参数标签，而是拥有不同动作、攻击窗口和应对方法。

#### 行为原型

| 行为 | 基础攻击 | 玩家应对 |
|---|---|---|
| `chaser` | 短距离扑咬、近身追击 | 后撤或跳跃 |
| `charger` | 蓄力、高速冲锋、撞墙硬直 | 侧移或闪避 |
| `shooter` | 瞄准预警线、定向弹幕 | 横向走位 |
| `guardian` | 震地、范围弹、召唤 | 拉开距离或优先清小怪 |
| `flying` | 俯冲、越顶射击 | 预判落点 |

#### 数据协议

新增可复用技能定义：

```ts
interface CombatAbility {
  id: string;
  type: "projectile" | "charge" | "slam" | "summon" | "breath";
  windupMs: number;
  activeMs: number;
  recoveryMs: number;
  cooldownMs: number;
  range: number;
  damage: number;
  telegraph: "line" | "circle" | "cone" | "none";
}
```

敌人配置只引用技能 ID 和阶段，不直接生成代码或任意脚本。

#### 验收标准

- 所有会造成伤害的攻击都有至少 `350ms` 的视觉前摇。
- 每种行为至少有一个可区分的主要攻击。
- 所有技能都能通过移动、跳跃或防御处理。
- 攻击动画、前摇、命中窗口和后摇使用同一组时间数据。

---

### P0-2 可战斗的平台与危险物

#### 目标

让生成出的浮台、掩体、冰面和熔岩裂缝真正参与战斗，而不只是背景装饰。

#### 场地模板

先实现四种确定性模板：

1. **开阔战场**：适合追踪和冲锋敌人。
2. **双层平台**：高地提供射击优势，但敌人能够抵达。
3. **Boss 掩体场**：用于躲避直线弹幕。
4. **危险物走廊**：冰面、熔岩或毒雾等区域有明确安全路径。

#### 编译器职责

- 模型只输出场地语义、敌人组合和危险物偏好。
- 编译器负责坐标、平台尺寸、危险物安全区和可达性。
- PVE 玩家物理恢复对非地面平台的支持。
- 敌人使用简化移动规则，避免浮台与地面之间卡死。

#### 验收标准

- 生成器创建的浮台均可站立。
- 每个浮台和危险物都有对应的可玩性校验。
- 敌人不能进入玩家无法攻击或无法到达的永久安全区。
- 冰面、熔岩等危险物至少影响移动或伤害中的一项。

---

### P0-3 Boss 两阶段与专属战场

#### 目标

让 Boss 成为一局战斗的高潮，而不是高血量小怪。

#### 推荐结构

```ts
interface BossPhase {
  hpBelow: number;
  abilities: string[];
  movePattern: "keep_distance" | "aggressive" | "stationary";
}
```

#### 首版 Boss 模式

1. **第一阶段**
   - 远程冰弹/元素弹
   - 保持中距离
   - 低频召唤小怪

2. **第二阶段**
   - 增加直线吐息或地面冰刺
   - 缩短攻击间隔
   - 血量降至 50% 时显示阶段切换

#### 验收标准

- 每个 Boss 至少有两种可辨认技能。
- 至少发生一次明确的阶段切换。
- Boss 战拥有独立触发点和场地边界。
- 技能均留有可行动的安全区。

---

### P0-4 敌人动作包 V2

#### 目标

让自定义敌人动作适合横版战斗，而不只是展示正面的基础循环。

#### 动作契约

```text
idle / walk / windup / attack / hurt / death
```

#### 生成要求

- 小怪和 Boss 至少拥有侧视 `walk / attack`。
- `windup` 可与 `attack` 合并，但必须有明确前摇帧区间。
- `hurt` 和 `death` 可先使用程序化回退，但要预留动作槽位。
- 动作元数据记录命中起始帧、结束帧、帧率和循环类型。
- 已生成敌人支持单独重建某个动作，不必整只重新生成。

#### 验收标准

- 横版移动时不再长期使用正面动作假装侧视。
- 攻击动画与实际伤害窗口一致。
- 受击和死亡至少有闪白、击退或淡出之外的专用表现。
- 单个敌人的动作资源可通过统一清单预加载。

## P1：P0 稳定后进入

### P1-5 闪避与瞄准

#### 目标

只增加一个高价值主动操作，暂不引入技能树。

#### 方案

- 鼠标、触控或方向键调整攻击角度。
- 保持一次输入发射一次攻击，不改成持续扫射。
- 增加短距离闪避，带短暂无敌帧和冷却。
- 闪避与单格防御形成两种处理方式：
  - 防御：挡住一次确定伤害，之后进入冷却。
  - 闪避：主动离开危险区，适合处理连续弹幕。

#### 验收标准

- 玩家可用瞄准命中空中或高台敌人。
- 闪避具有清晰的起止、无敌窗口和冷却反馈。
- 键鼠、键盘和触控操作均可用。

---

### P1-6 战斗自动验证

#### 需要检查

- 预计战斗时长是否落在目标区间。
- 敌人技能是否留下安全区。
- 同屏敌人和投射物是否超过性能预算。
- 是否存在玩家无法到达的远程攻击位置。
- 玩家是否可能被连续攻击锁死。
- 当前难度下是否存在明显过长的 Boss 战。

#### 输出

- 可玩性通过/失败。
- 具体失败原因。
- 建议调整的敌人生命值、攻击间隔或场地尺寸。

---

### P1-7 战斗评级与重玩

#### 推荐指标

- 战斗评级：S / A / B / C。
- 通关时间。
- 受伤次数。
- 防御成功次数。
- 最高连击或连续无伤输出。
- 首次击败和最佳记录。

#### 重玩入口

- 同场景换阵容再战。
- 结算页直接重试。
- 每局随机 1–2 个可读规则词缀，例如：
  - 敌人生命 `+20%`，玩家移速 `+10%`。
  - Boss 技能加速，但防御冷却缩短。

## P2：后续扩展

### P2-8 多场景连续章节

- 将多个 PVE 场景串联为章节。
- 章节间保留生命、防御次数或积分状态。
- Boss 前增加小型事件或对白。

### P2-9 场景包导入导出

- 导出场景、敌人引用、数值和动作清单。
- 导入时校验依赖资产是否存在。
- 支持团队共享同一套 PVE 关卡配置。

### P2-10 2.5D 纵深模式

- 新增纵深坐标、前后遮挡和深度碰撞。
- 不替代当前 2D 模式，作为独立玩法选项。
- 仅在 P0/P1 的战斗循环已经稳定后启动。

## 4. 推荐研发顺序

### 阶段 A：战斗基础设施

1. 定义 `CombatAbility`、`BossPhase`、`ArenaTemplate`。
2. 将现有四种行为迁移到技能配置。
3. 补齐攻击前摇、命中窗口和后摇。

### 阶段 B：地形与 Boss

1. 恢复 PVE 平台物理。
2. 加入第一套危险物。
3. 实现 Boss 两阶段和独立战场。

### 阶段 C：动作与玩家操作

1. 生成侧视动作和前摇/受击动作。
2. 加入瞄准与闪避。
3. 调整移动端控制布局。

### 阶段 D：质量与重玩

1. 接入战斗模拟和自动校验。
2. 增加战斗评级和最佳记录。
3. 完成性能、移动端和无障碍回归。

---

## 5. V3.0 验收门槛

V3.0 达到以下条件后再进入章节或 2.5D：

- 一局普通 PVE 目标时长约为 90–150 秒。
- 至少有两种行为完全不同的普通敌人。
- Boss 有两个阶段、至少三种技能。
- 玩家能够通过移动、闪避或防御处理所有攻击。
- 浮台和危险物真正参与碰撞或战斗。
- 自定义敌人拥有可用于横版战斗的侧视动作包。
- 战斗生成支持自动可玩性验证。
- 关键动作、攻击前摇和胜负状态均有文本或形状提示，不只依赖颜色。
- 桌面与移动端均可完成完整战斗流程。

## 6. 暂不纳入 V3.0

- 七章完整剧情模式。
- 复杂技能树和装备系统。
- 每局实时生成新动作。
- 多人在线 PVE。
- 完全自由编辑的任意脚本技能。
- 2.5D 纵深操控。

这些功能应当建立在 V3.0 的战斗语法、数据协议和自动验证稳定之后。
