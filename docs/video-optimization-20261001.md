# 视频生产模块系统性优化 — 实施与评估报告（2026-10-01）

> 范围：视频生产全链路（DashScope i2v → 抽帧选帧 → 循环合成 → 落盘分发 → 前端消费）。
> 方法论：先建测量、再动手；每一轮改动都用同一把尺子（离线确定性基准）对照基线。
> 结论先行：**循环时长 ×1.500 达成（1.667s → 2.500s），七项质量指标全部不降级**，
> 其中帧间运动均匀度（motion_cv）改善 43%；模块衔接层修复 1 个实测故障（tmp 竞态），
> 新增 14 项契约测试全绿。

## 0. 基准测量机制（先于一切优化）

`benchmark/video_quality.py`——全离线、确定性、零额度。度量对象是本仓库的**转换
管线**（不是生成模型本身，i2v 是黑盒且按次计费）。合成视频忠实模拟 i2v 输出形态：
静态开头 + 非匀速运动主体（缓入缓出）+ 渐变彩色背景 + 高光/暗部固定区块。

指标体系（对应任务要求的三类质量）：

| 指标 | 定义 | 质量门（vs 基线） |
| --- | --- | --- |
| loop_seconds | 循环时长 = 帧数/fps | 目标 ×1.5（达成率报告） |
| sharpness | 逐帧亮度 Laplacian 标准差均值 | ≥ ×0.97 |
| temporal_consistency | 相邻帧 similarity_rgba 均值 | ≥ −0.02 |
| color_fidelity | 逐帧 RGB 直方图与源帧余弦相似度 | ≥ −0.01 |
| dynamic_range_spread | 亮度 1%~99% 分位差（高光/暗部裁剪率随录） | ≥ −3.0 |
| motion_total | 循环动作总量（Σ帧间能量）——采样密度变化下的**不变量** | ≥ ×0.90 |
| motion_cv | 帧间运动能量变异系数（动作流畅度） | ≤ ×1.05 |

配置指纹 `VIDEO_SAMPLE_MIN_COUNT / VIDEO_SAMPLE_DURATION` 固化在
`animation_service/service.py`，基准与生产路径同源；参数变更必须重录基线。

## 1. 目标设定

- **循环时长**：+50%（1.667s → 2.5s）。依据：i2v 源视频 5s/24fps ≈ 120 帧，
  旧采样仅取 20 帧（时间采样率 17%），步距 0.21s/帧是动作丢信息与卡顿的来源。
- **质量红线**：上表七项指标任何一项不得低于优化前水平。
- **模块衔接故障率 ≤ 0.1%**：离线契约/压力/浸泡矩阵中可归因于衔接层的故障为 0
  （见 §4；统计意义的 0.1% 需生产遥测，机制已就位——`error_kind` 分类落账）。

## 2. 五轮迭代记录（实测数据）

| 轮次 | 改动 | loop_seconds | motion_total | motion_cv | sharpness | 质量门 |
| --- | --- | --- | --- | --- | --- | --- |
| R1 基线 | —（20 帧/1.0s，均匀采样） | 1.667 | 18.72 | **0.5247** | 13.656 | — |
| R2 | 采样密度 20→30 帧 / 1.25s | 2.500（×1.500） | 18.41 | 0.5427 | 13.657 | PASS* |
| R3 | 动作感知选帧（累计运动量等分） | 2.500（×1.500） | 18.56 | **0.3010**（×0.574） | 13.716 | PASS |
| R4 | 衔接强化（边界校验/竞态修复/内存封顶） | 2.500 | 18.5± | 0.301 | 13.72 | PASS |
| R5 | 全量回归 | 2.500 | 18.5± | 0.301 | 13.72 | PASS |

\* R2 曾触发 motion_mean 门 FAIL——这是**指标定义缺陷**而非质量退化：帧数 20→30
后同样的动作总量摊到更多帧，单帧能量必然 ∝ 1/帧数。已把质量门修正为正确不变量
`motion_total`（循环动作总量），R2 实测 0.983、R3 实测 0.991，动作信息无损。

R3 核心收益：`_select_by_motion` 在候选帧（3× 预算，封顶 64）的**累计运动曲线**
上等分取点——运动快的段自动多分帧、静止开头自动跳过，帧间能量均匀化
（CV 0.525 → 0.301）。这正是"相邻关键帧过渡平滑"的量化形态。
R4 的条带内存封顶（288px/帧）保证试玩舞台五条 30 帧条带的解码内存回到 20 帧
时代水平（~59MB 持平），交付 GIF 仍为全量 30 帧。

## 3. 动作精细度：技术瓶颈分析（为什么无法更高）

控制面与天花板（当前技术条件下的诚实边界）：

1. **i2v 模型是黑盒**：wan2.2-i2v-plus/flash 输出固定 ~5s、无时长/动作幅度/
   关节参数可调；可用的旋钮只有 prompt、尺寸、prompt_extend。动作精细度的
   上限由模型的时间一致性决定，本管线无法突破，只能"不丢不糊地搬运"。
2. **额度约束下的迭代方式**：prompt 侧的精细度优化（动作描述 AI 增强、
   FRAMING_CLAUSE 构图锁、审核安全改写）已在上午落地并实机验证（76s 出片
   实测）；本次五轮迭代使用离线确定性基准，保证管线层优化可量化可复现；
   逐轮实机 A/B 每轮需 5×90s 真实生成额度，不适合作为回归门禁。
3. **微表情/物理模拟**：i2v 路线的微表情与重力表现完全由源模型决定；程序化
   骨骼路线（晚间已完成的曲线 C1 化/生物力学/次级动作）覆盖了离线可测的
   精细度维度。剩余差距 = 模型固有限制，非管线缺陷。

**可进一步提升的前置条件**（记录待办）：换用支持时长/运动强度参数的新一代
i2v 模型；或接入局部重生成（对 CV 异常段二次采样）——两者都受模型可用性与
额度限制，当前不具备条件。

## 4. 模块衔接强化（测试矩阵与修复）

新增 `tests/test_video_pipeline.py`（14 项，离线）：

| 类别 | 用例 | 结果 |
| --- | --- | --- |
| 边界异常 | 空 / 400B 截断 / 4KB 垃圾数据 → 可读中文错误（不抛解析异常风暴） | 3/3 PASS |
| 轮询契约 | 401 → 立即失败且分类 auth（自动换 Key）；404 → fatal | 2/2 PASS |
| meta 契约 | 落盘字段集合（frame_urls/urls 三件套/created_at…）+ 文件真实落盘 | 3/3 PASS |
| 高并发 | 6 线程并行抽帧+合成：全部成功、结果可区分、时间有界 | 3/3 PASS |
| 浸泡 | 30 轮顺序循环：全成功、时间有界、tmp 零残留 | 3/3 PASS |

**实测修复的衔接故障**：Windows 下 ffmpeg 子进程退出与临时文件删除存在竞态，
浸泡 30 轮命中 1 次（`PermissionError` 被静默吞掉 → tmp 残留）。修复：
reader 在 finally 中必关 + 主线程快删失败交后台收割线程退避重试（30s 窗口），
磁盘清理最终一致、生成主流程零阻塞。诊断过程中否决了两条歧路
（O_TEMPORARY 与 imageio 的按路径重开不兼容；固定 sleep 重试窗口不可靠）。

告警/自动恢复链路（已有机制，本次接入闭环）：classify_error 五分类 →
Key 池自动切换 / 网络退避重试 / 审核安全改写 → VideoGenerationError(kind)
→ 批次条目 error_kind → 试玩舞台中文徽章 + usage_ledger 台账。
